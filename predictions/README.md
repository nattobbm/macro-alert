# 预测日志

## 为什么存在

**不写下来的理解无法结算。**这个目录的唯一目的是把"看懂了"变成可测量的判断力。

核心纪律来自两条已确立的方法论：
1. **结果偏差禁令**：用结局给决策打分 = 用运气给判断力打分
2. **决策质量与结局分离**：两条线并行记录

## 目录

```
predictions/
├── open/       未结算
├── settled/    已结算
├── void/       因前提消失而作废（不计入Brier样本）
└── scorecard.md
```

## 流程

### 1. 事前（锁定）
- 填 `probability` 与 `reasoning_ex_ante`
- **锁定前必须核实所有二手数据的一手来源**（见每个文件的 `data_conflict` 栏）
- `git commit` → commit时间戳即预注册时间证明
- 可选：OpenTimestamps 加盖比特币锚定时间戳（免费、无需注册）

### 2. 锁定后
**禁止修改 `probability` 与 `reasoning_ex_ante`。**修改历史在git中可查。

失效条件（falsifiers）发生时：**记录，但不改概率**。改了就不是预注册。

### 3. 结算
移入 `settled/`，填：

| 字段 | 内容 |
|---|---|
| `outcome` | 0 或 1 |
| `settlement_note` | 实际发生了什么 |
| **`quality_self_score`** | **事前信息下这个概率是否合理（1-5分）。可在结局公布前先自评。** |
| `failure_mode` | 若错，属哪一类：机制错 / 时点错 / 数据错 / 纯随机 |

### 4. 记分
- **Brier score**：`sklearn.metrics.brier_score_loss`
- **校准曲线**：`sklearn.calibration.calibration_curve(n_bins=5)`
- **硬门槛：累计已结算样本 < 50 时只记录不解读。**看板上照实标注 n。

## 四格表（结算时归位）

| | 好决策 | 坏决策 |
|---|---|---|
| **好结局** | 应得 | **运气**（最危险——会强化错误流程） |
| **坏结局** | **不走运** | 应得 |

对角线容易，非对角线才是全部难点。**只看结局的人永远分不出这两类。**

若长期出现"决策质量高但结局差" → 模型有系统偏差。
若出现"结局好但质量低" → **在靠运气，比亏钱更危险。**
